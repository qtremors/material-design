Purpose

Experience, understand, and locate Material implementation

The running app is the visual and behavioral reference, the catalog explains design intent and API status, and the repository is the implementation truth. Users search an official name or alias, exercise real states, read use and avoid guidance, inspect accessibility and adaptation, separate API stability from artifact availability, and copy real source paths.

The app contains no accounts, ratings, simulated installs, lesson progress, remote catalog, or placeholder demonstrations.

State and search

Immediate input, off-main derivation

The ViewModel exposes independent flows for catalog load, root destination, category, API stability, query, search, bookmarks, recents, settings, and one-shot events. Search text updates immediately; non-empty result work is debounced and runs away from the main thread. Exact names and API symbols rank ahead of aliases, categories, summaries, and guidance.

Privacy

Offline by construction

  • No internet permission, ads, analytics, telemetry, trackers, account, or remote service.
  • The bundled catalog works without network access.
  • Preferences remain local and are excluded from cloud backup and device transfer.
  • Official documentation and project links open in another app only after user action.

Verification and release

Tests and artifacts validate the same contract

Build-logic, catalog, DataStore, motion, ViewModel, demo registry, backup rules, and navigation have focused coverage. Release builds add lint vital analysis, R8 optimization, resource shrinking, deterministic APK naming, and local signing when all ignored credentials are present.

cd material-app
.\gradlew.bat -p build-logic :convention:test --warning-mode all
.\gradlew.bat testDebugUnitTest verifyMaterialBuildConventions checkProductionStrings --warning-mode all
.\gradlew.bat :app:assembleDebug --warning-mode all
.\gradlew.bat :app:assembleRelease --warning-mode all

The application version is read from gradle.properties, not duplicated on this page. A release is ready only after APK metadata, signing identity, and checksum are verified.
