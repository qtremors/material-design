Why this learning project exists

Knowing the rules is not the same as knowing how to design.

Material Design remains difficult for people and language models because its quality comes from relationships and judgment. An interface can use valid components and tokens yet still feel generic, crowded, unbalanced, inaccessible, or emotionally flat.

account_tree

It is a system

Color, type, shape, space, motion, and components influence one another. Treating them as isolated recipes produces inconsistent results.

touch_app

It must behave

Every component needs meaningful states, feedback, focus, semantics, input support, and adaptive behavior—not only a polished default screenshot.

auto_awesome

Expression needs purpose

Material 3 Expressive uses emphasis, contrast, shape, typography, and motion to clarify personality and priority. Decoration without intent becomes noise.

psychology
The goal is transferable design judgment.

Study why a decision works, compare alternatives, inspect every state, and learn when platform conventions should differ. Do not merely copy the final pixels.

Foundations before components

Build the visual language as one connected system.

Start with the job the interface must do. Establish hierarchy and relationships before choosing individual components.

palette

Color communicates roles

Use surface and content roles to express hierarchy, state, and emphasis. Check contrast in every theme instead of selecting colors by appearance alone.

text_fields

Typography creates rhythm

Choose type roles by reading order and purpose. Size, weight, width, line height, and spacing should make hierarchy obvious before color is added.

category

Shape carries personality

Use a small, intentional shape family. Let contrast in corners or silhouettes signal importance, grouping, selection, or transformation.

space_dashboard

Layout explains relationships

Spacing is structural information. Align related content, separate unrelated content, preserve breathing room, and adapt composition rather than merely shrinking it.

animation

Motion explains change

Animate continuity, causality, focus, and spatial relationships. Motion should help a user understand what changed and remain respectful of reduced-motion preferences.

accessibility_new

Accessibility shapes the design

Contrast, semantics, target size, focus order, keyboard support, zoom, screen readers, and alternate motion are design inputs—not final QA additions.

A repeatable design workflow

Reason from intent to verification.

This order keeps design decisions coherent and gives humans or agents concrete checkpoints before implementation becomes expensive.

  1. 1

    Define intent and audience

    State the user goal, primary task, emotional tone, environment, and platform constraints in plain language.

  2. 2

    Establish hierarchy

    Decide what must be noticed first, what supports it, what can wait, and which actions deserve the strongest emphasis.

  3. 3

    Model content and states

    List real content, actions, selection, loading, empty, error, disabled, focus, hover, pressed, dragged, and completion states.

  4. 4

    Compose adaptively

    Design compact, medium, expanded, and in-between layouts. Recompose navigation and grouping when space or input mode changes.

  5. 5

    Add expression with purpose

    Use type, shape, color, and motion to reinforce the chosen hierarchy and emotional tone rather than decorating every surface equally.

  6. 6

    Verify in context

    Test real text, long labels, themes, zoom, keyboard, touch, assistive technology, reduced motion, interruption, and recovery.

Choose by interaction role

Components are decisions, not a catalog.

Start from what the user needs to understand or do. Select a component only after its role, prominence, state model, and surrounding layout are clear.

ads_click

Actions

Buttons, FABs, split actions, and toolbars express what can happen next. Match prominence to consequence and frequency.

explore

Navigation

Bars, rails, drawers, tabs, and suites explain location and movement. Adapt the navigation model instead of forcing one shell everywhere.

tune

Input and selection

Fields, chips, switches, sliders, and segmented controls need clear labels, validation, affordance, focus, and reversible state.

view_agenda

Containment

Cards, sheets, dialogs, lists, and sections group information. Use containers only when their boundaries clarify relationships.

progress_activity

Feedback and progress

Indicators, banners, snackbars, and state changes keep users oriented. Explain what is happening, what completed, and what they can do next.

responsive_layout

Adaptive composition

Window size, posture, density, input method, language, and content length can change the layout strategy without changing its intent.

One subject, two learning modes

Guidance for humans and coding agents.

Both should learn the same design intent. Their working methods differ, so each needs a deliberate practice loop.

person

For human designers and developers

  • Observe real interfaces and name the hierarchy you perceive.
  • Recreate small components, then explain every visual decision.
  • Compare multiple valid compositions instead of chasing one canonical screen.
  • Manipulate tokens and content to learn which relationships are robust.
  • Test with real input, accessibility settings, and constrained screens.
Follow the complete learning guide →
smart_toy

For LLMs and coding agents

  • Translate the request into user intent, hierarchy, states, and constraints before coding.
  • Inspect existing project patterns and platform conventions instead of inventing isolated styling.
  • Generate deliberate alternatives and explain why one composition best serves the goal.
  • Use semantic components and complete interaction states, not screenshot-shaped markup.
  • Self-review at multiple widths and input modes for generic, repetitive, or decorative decisions.
