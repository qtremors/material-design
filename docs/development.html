Lifecycle

From source to a working Android reference

  1. 1

    Build modular source

    Create a state-hoisted implementation in the matching Material domain without feature, navigation, or persistence dependencies.

  2. 2

    Register exact metadata

    Add the official name, aliases, API maturity, working demo key, and repository-relative source path to the validated catalog.

  3. 3

    Verify before exposing

    Check interaction states, semantics, accessibility, adaptive layouts, search, and representative light/dark configurations.

  4. 4

    Publish the reference

    Only working entries appear in the app. Keep unfinished components in the task backlog and update documentation and the changelog.

Change discipline

Keep public guidance current

  • Update the root changelog for every user-visible change and preserve its release history.
  • Keep release notes user-relevant instead of recording internal experiments.
  • Do not change application versions unless explicitly requested.
  • Keep browser documentation and relevant HTML skills aligned.
  • Document platform differences instead of hiding them behind false parity.
