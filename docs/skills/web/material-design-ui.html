Material Design UI & UX Design Skill

Design, style, and review framework-free web interfaces according to Material Design 3 and Material 3 Expressive foundations.

This skill defines the visual language and user-experience standards for the independent web implementation. Use it with material-expressive-development.html, the web development guide, and the Markdown version for agents and harnesses.

The Android app is a UI/UX reference only. Do not copy Compose APIs, state models, or source code into web components.

1. Visual Language & Aesthetics

Use Material 3 foundations and add expressive emphasis deliberately. Visual novelty must not weaken hierarchy, state clarity, accessibility, or task completion.

  • The Color System: Everything is driven by design tokens.
    • Token Compliance: Use semantic custom properties for product UI. Raw colors are acceptable only inside token definitions, illustrations, or isolated test fixtures.
    • Usage: Components must use --md-sys-color-* tokens (e.g., on-surface-variant, primary-container).
  • Typography: Establish a clear, consistent hierarchy.
    • Headline/Title: Use Roboto (Standard) or Roboto Flex (Expressive) for emphasis.
    • Body/Label: Use Roboto for clarity.
  • Surfaces: Choose surface-container roles by hierarchy and contrast, not decoration alone.
  • Themes: Support light and dark color schemes. Treat any OLED treatment as a project option, not a Material requirement.

2. Typography & Hierarchy

Typography in MD3 is not just about size; it's about communicative weight and structure.

  • Font Families:
    • Standard: Roboto (Default).
    • Expressive: Roboto Flex (Variable). Used when data-style="expressive" is active.
  • The Type Scale:
    • Display: High-emphasis screens (e.g., Hero headers).
    • Headline: Page titles.
    • Title: Card headers.
    • Body: Readable content (16px base).
    • Label: Small metadata/buttons.
  • Expressive Type:
    • Leverage font-variation-settings: 'wdth' 115 on Roboto Flex for dynamic headers.

3. Layout & Adaptability

Designs must be fluid and adapt across all screen sizes.

  • Standard Spacing:
    • Use 8px grid multiples (8px, 16px, 24px, 32px, 48px).
  • Adaptive Containers:
    • Compact (< 600px): Prioritize one-pane layouts and compact navigation suited to the content.
    • Medium (600px–839px): Consider navigation rails and additional panes when the task benefits.
    • Expanded (≥ 840px): Use the space for stronger hierarchy or multi-pane layouts; do not merely stretch compact UI.
  • Grid Systems: Use repeat(auto-fill, minmax(300px, 1fr)) for responsive dashboards.

4. Shapes & Sizing

Material Design 3 uses rounder shapes and larger targets than MD2.

  • Corner Radiuses:
    • Buttons: Full Round (--md-sys-shape-corner-full).
    • Cards: Extra Large (--md-sys-shape-corner-extra-large).
    • Standard: Medium/Large (--md-sys-shape-corner-medium).
  • Interaction Targets: Prefer at least 48x48px for primary custom controls and never fall below WCAG 2.2 target-size requirements without an applicable exception.

5. Elevation & Feedback

Elevation is communicated through Shadows and State Layers. Note: In OLED/Dark modes, elevation is often replaced or augmented by borders (outline-variant) for contrast.

  • Elevation Levels:
    • Level 0-5 using --md-sys-elevation-*.
  • Interaction Feedback:
    • State Feedback: Provide visible hover, focus, pressed, selected, loading, and disabled states where they apply. A ripple is optional web presentation, not the only state indicator.
    • State Layers (Overlay Opacity):
      • Hover: 8% (0.08)
      • Focus/Pressed: 12% (0.12)

6. Motion & Feel

Motion should feel physical and purposeful.

  • Duration: Choose the shortest duration that preserves continuity and comprehension; centralize values as motion tokens.
  • Easings:
    • Standard: cubic-bezier(0.2, 0, 0, 1).
    • Emphasized: Use the project's emphasized motion tokens for enter, exit, and spatial transitions.
    • Expressive motion: Use spring-like motion only where overshoot is safe, interruptible, and covered by reduced-motion behavior.

7. Review Checklist

Before finalizing a web surface, verify:

  1. Semantic color roles remain legible in light, dark, forced-colors, and high-contrast conditions.
  2. Typography, spacing, and shape communicate hierarchy without relying on color alone.
  3. Every interactive state has clear visual and semantic feedback, including visible keyboard focus.
  4. Motion is interruptible, respects prefers-reduced-motion, and never delays the core action.
  5. The layout reflows at 200% zoom and across compact, medium, and expanded viewports without losing content or state.
