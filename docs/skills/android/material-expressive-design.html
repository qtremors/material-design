Expressive design guide

Material 3 Expressive Design for Android

How the Material Design app builds a complete Material 3 Expressive product in Jetpack Compose, and how to build one the same way. Every rule here is implemented in core/designsystem and core/ui.

Principles

Expressive, not decorated

Meaningful expression

Shape, size, color, and motion carry meaning: a larger shape for the main action, connected shapes for grouped choices, a spring when something responds to touch.

Tonal surfaces

Pages sit on surfaceContainer, rows on surfaceBright, and groups of rows connect with 2 dp gaps. Shadows are rare.

One design system

Screens use the shared components. A screen that needs something new adds it to the design system, so every screen gets it.

Respect the person

Haptics and motion follow their settings. Nothing flashes, nothing jumps, and loading never looks like empty.

Theme

Modes, color sources, and generated schemes

MaterialDesignTheme wraps MaterialExpressiveTheme with a scheme, typography, shapes, and motion scheme from ThemeState.

  • Modes: System, Light, or Dark as connected choices, plus a pure black toggle that applies in dark mode.
  • Color source: wallpaper colors on Android 12+, a named preset seed, or a custom seed. Below Android 12, wallpaper falls back to the preset.
  • Generated schemes: seeds become full schemes through Material Color Utilities (MaterialKolor's tonal spot, or monochrome for a neutral preset), so every preset keeps proper contrast. Never hand-pick a whole scheme.
  • Pure black: pages go black while rows and raised parts step up in small neutral grays, so rows still read as separate.
  • Splash: keep the splash screen until stored settings load, so the first frame never uses the wrong colors.

Page and rows

surfaceContainer behind everything; surfaceBright for rows and content blocks.

Actions and selection

primary for the main action; secondaryContainer and primaryContainer for selected states.

Text hierarchy

Section headers in primary titleSmall; supporting text in onSurfaceVariant.

Decorative tints

Badges use a pastel palette hashed by key, so the same item always gets the same color in every theme.

Typography

Google Sans Flex on the Material type scale

One variable font file, with weights as instances, on the 15-role Material type scale. Large titles come from LargeFlexibleTopAppBar, row titles use bodyLarge, supporting text bodyMedium, and tags labelMedium. Counts use tabular figures; API symbols and paths use a monospaced code style. Layouts must survive 200% font scale without clipping.

Shape & spacing

Rounded tokens and connected groups

  • Shapes: 12, 16, 20, and 28 dp roles; never the 4 dp default on shipped components.
  • Connected groups: 24 dp outside, 6 dp inside, and 2 dp gaps between rows, so the page shows through as a hairline.
  • Fields: a 16 dp field shape on every text field; search fields are pills.
  • Expressive shapes: MaterialShapes for one hero element per screen and for the selected swatch in a picker.
  • Spacing: a 4 dp grid through MaterialTheme.spacing, with semantic gutters, row padding, section gaps, and clearance under the floating bar.

Components

The shared component set

AppScaffold

A large flexible top bar that collapses on scroll, with padding that already includes gutters and toolbar clearance.

FloatingTabBar

Tabs on top-level pages; on every other page it morphs into Back plus the page title.

Connected rows

ConnectedGroup, ConnectedItem, NavigationRow, and ToggleRow with ExpressiveSwitch.

Connected choices

Two to five short options as connected ToggleButtons; the selected one morphs round.

AppMenu

The Expressive menu with vibrant groups, opened by long-press on the item.

States

LoadingIndicator while loading; EmptyState with a soft shape, a title, a sentence, and an optional action.

Buttons always pass the pressed-shape variants so they morph when touched, and destructive actions confirm in a dialog that names what happens.

Navigation & adaptive

From the floating bar to rails and panes

  • Compact and medium: the floating tab bar, with search as its own full-screen page.
  • Expanded: a WideNavigationRail replaces the floating bar, and NavigableListDetailPaneScaffold keeps the list beside the open item with Material's pane motion.
  • Transitions: destinations slide and fade with the motion scheme's specs, and predictive back uses the same transitions. Tabs fade through and keep their scroll state.
  • Shared elements: an element that appears in both the list and the opened page carries the same key inside a SharedTransitionLayout, so it travels between them.

Motion & haptics

Springs with jobs, and respect for settings

Springs respond to touch with a slight Expressive bounce. Project springs live in one file and are named for their job: press feedback, spatial movement, settling, progress, and rejection. Official components keep their own physics. With Reduce motion on, decorative movement snaps while state changes, meaning, and safety timing stay. Haptics go through one helper that does nothing when the person turned them off.

API coverage

Accountable to the whole official API

The repository tracks every public symbol of the pinned Material 3 and Material 3 Adaptive artifacts in core/catalog/api/: a generated inventory, a coverage ledger, and a generated report. Tests check every catalog reference for existence, stability, availability, and reviewed version, and new upstream symbols fail the build until they are triaged.

Quality checklist

Before a screen ships

  • Every screen uses the scaffold with a large flexible top bar.
  • Lists are connected groups; toggles are toggle rows; one-of-a-few choices are connected toggle buttons.
  • Fields use the 16 dp shape and search fields are pills; buttons morph when pressed.
  • Menus open by long-press; loading and empty states never flash.
  • Expanded windows get the rail and panes; nothing assumes a phone.
  • Haptics and animations follow the person's settings.
  • Light, dark, and pure black checked at the smallest and largest font sizes.
